# ADR-002: Обновление площади является одной транзакцией

- Статус: принято
- Дата: 2026-08-05
- Область: admission и публикация центральной карты

## Контекст

После ADR-001 источники и производные данные разделены правильно, но операционный переход оставался составным:

1. отдельно разрешить текущие ревизии домов;
2. вручную обновить `SPACE_LOCK.json`;
3. получить snapshots;
4. пересобрать `SPACE_STATE.json`;
5. перерисовать README и GUIDE.

CI обнаруживал рассинхрон, но не создавал согласованный переход. Ошибка между шагами могла оставить центральный репозиторий в промежуточном состоянии.

## Решение

Добавляется `scripts/sync_space.py` — единая admission-транзакция площади.

```text
SPACE_REGISTRY + явные tracking_ref
→ разрешить каждый ref в exact commit SHA
→ получить HOUSE_STATE по exact SHA
→ проверить technical_repository и локальные инварианты
→ вычислить Git blob SHA
→ подготовить новый SPACE_LOCK
→ собрать SPACE_STATE
→ подготовить README и GUIDE
→ заменить все четыре выхода
```

До публикации все источники и все производные файлы собираются во временной области. При ошибке подготовки рабочие файлы не изменяются. При ошибке во время публикации уже заменённые файлы восстанавливаются из резервной копии.

## Два разных режима

### Admission

`sync_space.py` читает tracking refs, например `main`, только как вход для принятия нового состояния. Результатом становится новый exact lock.

### Reproducible build

`fetch_locked_houses.py`, `build_space.py` и `render_space_docs.py` не разрешают `latest`. Они проверяют и воспроизводят уже принятое состояние строго по exact revisions и blob SHA из lock.

Смешивать эти режимы запрещено:

```text
tracking ref → admission → exact lock
exact lock → reproducible build
```

## Контракт реестра

Каждая запись дома в `SPACE_REGISTRY.json` содержит:

- `house_id`;
- `repository`;
- `state_path`;
- явный `tracking_ref`.

Tracking ref не является частью доказательства воспроизводимости. Он лишь указывает, откуда admission-транзакция должна принять следующий exact commit.

## Выходы транзакции

Одна успешная операция публикует согласованный набор:

- `SPACE_LOCK.json`;
- `SPACE_STATE.json`;
- generated section в `README.md`;
- generated section в `GUIDE.md`.

Частичное успешное обновление не считается допустимым состоянием.

## Инварианты

- сначала проверяются все дома, затем изменяется первый выходной файл;
- exact revision и blob SHA записываются до сборки карты;
- карта собирается из тех же байтов, которые описывает новый lock;
- README и GUIDE строятся из той же карты;
- ошибка подготовки оставляет репозиторий неизменным;
- ошибка публикации запускает rollback;
- admission не изменяет дома;
- lock остаётся явным проверяемым актом принятия, а не скрытым чтением `latest`.

## Использование

Подготовить и проверить переход без записи:

```bash
python scripts/sync_space.py --dry-run
```

Принять текущие tracking refs и атомарно обновить площадь:

```bash
python scripts/sync_space.py
```

Для приватных источников используется `GITHUB_TOKEN`; секреты не записываются в registry, lock или карту.
